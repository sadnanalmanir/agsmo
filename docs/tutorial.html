Mental model

One picture for all lessons. A plan is a root Goal with ordered SubGoals — there is no separate Plan class.

Agent ──performedBy──► Action ──hasOutcome──► Outcome ▲ │ achievedBy Episode ◄──partOf── Goal/SubGoal ──hasConstraint──► Constraint │ └──hasSubGoal──► SubGoal (stepIndex 0..n)
  • status on goals: active · completed · failed · abandoned
  • stepIndex orders plan steps (0-based); next open step = lowest active index
  • rationale on actions answers “why did you do X?”
  • Actions/Outcomes are also typed as prov:Activity / prov:Entity

agsmo:goal-write-abstract a agsmo:Goal ;

  agsmo:status "active" .
You should observe Exactly one Goal; status active; zero Actions.

02 Plan with constraints

A multi-step plan = root Goal + ordered SubGoals + Constraints. Still no actions.

01 minimal02 plan03 action04 full05 failure

Story

Ship a library release under offline-friendly and small-API constraints. Three ordered steps; all still active.

Goal (plan): Ship MVP status=active ├── Constraint: offline-capable ├── Constraint: small public API ├── SubGoal [0] Write core memory API active ├── SubGoal [1] Add unit tests active └── SubGoal [2] Publish docs active ↑ next open step = stepIndex 0

Key triples

agsmo:goal-ship-mvp a agsmo:Goal ;
  agsmo:status "active" ;
  agsmo:hasConstraint agsmo:constraint-offline ;
  agsmo:hasSubGoal agsmo:goal-write-api ,
                   agsmo:goal-add-tests ,
                   agsmo:goal-write-docs .

agsmo:goal-write-api a agsmo:SubGoal ;
  agsmo:stepIndex 0 ;
  agsmo:status "active" .
You should observe Three SubGoals with stepIndex 0,1,2; next open step is 0; root has ≥2 constraints.

03 Action, outcome, explain

Execute one step: Action + Outcome + rationale for explainability. PROV dual-typing included.

01 minimal02 plan03 action04 full05 failure

Story

The agent implements plan APIs offline-first, records why, and marks the step completed via a successful outcome.

SubGoal [0] Write core memory API completed └── Action: Implemented create_plan… rationale: offline tests; small API… └── Outcome: tests green success=true

Key triples

agsmo:goal-write-api agsmo:achievedBy agsmo:action-implement-api .

agsmo:action-implement-api a agsmo:Action , prov:Activity ;
  agsmo:rationale "Plan APIs must live…" ;
  agsmo:hasOutcome agsmo:outcome-api-green ;
  prov:wasAssociatedWith agsmo:agent-alice .

agsmo:outcome-api-green a agsmo:Outcome , prov:Entity ;
  agsmo:success true ;
  prov:wasGeneratedBy agsmo:action-implement-api .
You should observe Non-empty rationale; outcome success true; goal linked with achievedBy. This is how “Why did you do X?” is answered from the graph.

05 Failure and roll-up

Not only happy paths: a failed step with no open work left → root plan failed.

01 minimal02 plan03 action04 full05 failure

Story

CI deploys staging (ok), then e2e fails. Plan root is marked failed.

Goal: Run integration on staging status=failed ├── SubGoal [0] Deploy staging completed success └── SubGoal [1] Run e2e failed success=false

Contrast with lesson 04

In 04 the root stays active because step 1 is still open. Here both steps are terminal and one failed → root failed.

agsmo:goal-fragile agsmo:status "failed" .
agsmo:outcome-e2e-fail agsmo:success false .
You should observe Root status failed; step 0 completed; step 1 failed; at least one Outcome with success false.

Try it (Python)

Always parse the ontology first, then an example file.

from rdflib import Graph

g = Graph()
g.parse("ontology/agsmo.ttl", format="turtle")
g.parse("examples/04_literature_review_full.ttl", format="turtle")

q = """
PREFIX agsmo: <https://w3id.org/agsmo/ns#>
SELECT ?step ?desc WHERE {
  ?sg a agsmo:SubGoal ;
      agsmo:status "active" ;
      agsmo:stepIndex ?step ;
      agsmo:description ?desc .
}
ORDER BY ?step
LIMIT 1
"""
for row in g.query(q):
    print(int(row.step), row.desc)
# Expected: 1 Summarize key architectures and trade-offs
